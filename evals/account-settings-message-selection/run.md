# Run the account-settings message-selection evaluation

Use this runbook when the user asks to create a baseline or run the eval for
`account-settings-message-selection`.

## Select the run type

Determine the run type from the user's request:

- **Baseline run:** "Create a baseline", "make a baseline", and equivalent
  wording. Write the scores to `baseline.md`.
- **Eval run:** "Run the eval", "create an eval run", and equivalent wording.
  Write the scores to `results.md`.

If the requested run type is genuinely unclear, ask before starting.

## Inputs

All paths are relative to this directory:

| Purpose | Path |
| --- | --- |
| Settings | `eval.json` |
| Child prompt | `prompt.md` |
| Scoring criteria | `rubric.md` |
| Baseline output | `baseline.md` |
| Eval output | `results.md` |

Read `eval.json` for the attempt count, model, required source files, setup
command, required installed files, child exclusions, required attempt evidence,
and validation command. Do not hard-code those values in this runbook.

## Source

Always evaluate the current branch tip. Record `git rev-parse HEAD` before
starting and use that exact commit for every attempt in the run.

Record any working-tree changes in the output metadata. Working-tree changes
are not part of the source commit and must not leak into child attempts.

Record the required source files from `eval.json` in the source manifest. Stop
if any required file is missing from the source commit.

Files generated by the configured setup command are not source files. Verify
them in each sanitized workspace after setup instead of requiring them in the
source commit.

## Run protocol

1. The parent agent coordinates and scores the run. It must not perform the
   child task itself.
2. Read the settings, prompt, rubric, and selected output file.
3. Before launching attempts, identify at least one expected retrieval path for
   every configured attempt-evidence artifact. Evidence does not need to come
   directly from the child execution interface if equivalent first-party
   evidence can be recovered after the attempt. Record the planned retrieval
   paths in the run artifacts.

   Accepted evidence sources are:

   - `finalResponse`: the child transcript or the final assistant-message event.
   - `toolTrace`: the runner trace, or session event and tool-execution records
     reconstructed in order. A recovered trace must include tool names,
     arguments, completion status, and result or error summaries.
   - `workingTreeDiff`: a Git diff from the sanitized workspace's initial
     commit to its final state.
   - `validationOutput`: the parent running the configured validation command
     in the child's final workspace and capturing stdout, stderr, and exit
     status.

   A missing direct retrieval API is not by itself a reason to block the run.
   Stop before launch only when there is no credible first-party recovery path
   for the source identity, workspace identity, child completion state, or
   working-tree diff. These are needed to associate evidence with the correct
   isolated attempt.
4. Read the prompt into the parent before preparing child workspaces.
   Materialize each child workspace from the recorded source commit while
   excluding every configured child-excluded path. The sanitized workspace must
   not retain the source repository's `.git` directory or history, because a
   child could recover excluded files with commands such as `git show`.
5. Initialize a fresh Git repository in each sanitized workspace and commit the
   sanitized snapshot before the child starts. This keeps child diffs reliable
   without exposing the source history. Record the source commit and excluded
   paths in the output metadata.
6. Verify that excluded paths are absent from every child workspace. This must
   hide the prompt, rubric, runbook, settings, baseline, prior results, prompt
   variants, and stored traces. If an excluded artifact is visible or appears in
   a child tool trace, mark the run `Contaminated` and do not use it for a causal
   comparison.
7. Run the configured setup command in each sanitized workspace. Stop if setup
   fails or if any configured required installed file is absent afterward.
   Setup output is parent preparation evidence and must not be shown to the
   child.
8. Create the configured number of fresh, isolated child sessions in the
   sanitized workspaces. Use the configured model for every child. Record every
   identifier returned during session creation, plus any project-session or
   child-session identifiers reported by later status and completion events.
   Associate them with the attempt's exact workspace path.
9. Send each child only the exact contents of `prompt.md`. Do not mention the
   evaluation, rubric, expected answers, baseline, previous attempts, or this
   runbook.

   A kickoff prompt supplied while creating a child session counts as the single
   prompt delivery. Never send the prompt again to that session.

   Do not infer launch failure from an empty diff, missing turns, stale session
   metadata, or delayed activity. Wait for an explicit completion or failure
   event. If records are eventually consistent, retry evidence retrieval for a
   bounded period after that event. Query using every recorded session
   identifier and the exact workspace path. Do not resend the prompt or message
   the child to manufacture missing evidence.

   If one child's state still cannot be determined, mark only that attempt
   `Blocked`. Continue collecting and scoring independent attempts. Mark the
   whole run `Blocked` only if no attempt has a trustworthy completion state or
   if the source and workspace identity cannot be established.

   If a child explicitly fails before starting, discard that attempt and create
   a new sanitized workspace and fresh session. Never reuse or restart the
   original attempt.
10. Let each child finish without guidance, correction, or retries. Do not
    archive or delete a child session until its evidence has been captured or
    all allowed recovery paths have been exhausted.
11. Capture the configured evidence outside the repository in the session
    artifact directory. Inspect each child's changes, final response, and tool
    activity. Run the configured validation command in that child's final
    workspace and record whether it passed.

    Recover missing evidence from the accepted sources in step 3. Preserve the
    recovered ordering and record which source supplied each artifact. Do not
    treat a child's claim that it read a file, used a token, or passed
    validation as a substitute for trace, diff, or command evidence.
12. Score every criterion as `Pass`, `Fail`, or `Unclear`, with concise evidence
    in the selected output file. Use `Unclear` only when all accepted recovery
    paths for the evidence needed by that criterion have been exhausted.

    Missing evidence affects only criteria that depend on it:

    - A missing tool trace makes trace-dependent criteria `Unclear`. It does not
      invalidate criteria that can be established from the final diff or
      deterministic validation.
    - A missing final response makes response-dependent criteria `Unclear`.
    - A missing diff makes implementation criteria `Unclear`.
    - A missing child-run validation log does not matter when the parent can run
      the configured validation command in the preserved final workspace.

    Continue scoring the remaining criteria and attempts. Record the run as
    `Completed with evidence gaps` when at least one attempt is scoreable but
    some criteria remain `Unclear`. Use `Blocked: incomplete instrumentation`
    only when no attempt can be scored meaningfully. Use `Contaminated` when
    isolation failed, even if the implementation otherwise appears correct.
13. Complete the summary after all attempts. For an eval run, compare the result
    with `baseline.md` when a completed baseline exists.

## Required eval summary table

After every eval run, include the same rubric comparison table in `results.md`
and in the parent agent's final response.

| Column | Required value |
| --- | --- |
| Rubric | Each criterion from `rubric.md`, in file order |
| Max | Criterion maximum |
| Baseline runs | Comma-separated attempt scores |
| Baseline avg | Mean baseline score |
| Eval runs | Comma-separated attempt scores |
| Eval avg | Mean eval score |
| Delta | Eval mean minus baseline mean |
| Total | Maximum score, comma-separated totals, mean totals, and delta |

Use one decimal place for averages and deltas. If no completed baseline exists,
use `N/A` for the baseline and delta cells. Do not replace this table with a
prose summary.

## Durable output

Store the complete findings in `baseline.md` or `results.md`. Do not copy child
worktrees, diffs, tool traces, logs, or other run artifacts into this
repository. The scored criteria and concise evidence are the durable record.
